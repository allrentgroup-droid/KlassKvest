# КлассКвест

HTML MVP (`index.html`) и отдельный начальный backend Node.js 24 / TypeScript / Fastify 5 / PostgreSQL 17.
ARGWork не используется: отдельные репозиторий, Compose project `klasskvest`, база, сети и секреты.

**Статус:** API реализован; HTML пока остаётся демонстрацией с localStorage. Выбор роли в HTML не является авторизацией. Интерфейс ещё не обращается к API, баланс на GitHub Pages не синхронизируется с PostgreSQL. Backend не содержит AI-проверки, чатов, геолокации, фото, платежей или публичного каталога пользователей.

## Возможности и правила

- Учителя создают классы, задания и раздельные голосования учеников/родителей.
- Пользователи, членство в классе и родительские связи создаются оператором через локальную CLI. Публичной регистрации и самостоятельного выбора роли нет.
- Ученик получает доступ к классу только при членстве и наличии согласия активного родителя. Родителю нужны собственное членство и связь хотя бы с одним активным учеником этого класса. Отзыв согласия действует на следующий запрос. Ссылка `consent_reference` — идентификатор документа в закрытом реестре оператора, а не сам документ.
- Ответы проверяются сервером. Правильные варианты, чужие ответы, логины, псевдонимы и списки детей не публикуются в API.
- **Одна окончательная попытка на задание.** Неверный ответ даёт 0; повторный запрос возвращает сохранённый результат. Это намеренное отличие от HTML-демонстрации с неограниченным перебором вариантов. Педагогический режим повторных попыток потребует отдельной модели и тестов.
- Ответ и начисление сохраняются в одной транзакции. `UNIQUE(task_id,student_id)` не допускает повторных ответов, `UNIQUE(answer_id)` — повторных начислений. Баланс вычисляется из журнала, отдельного изменяемого счётчика нет. Параллельные запросы не удваивают награду. `awarded` — награда сохранённого ответа, **не прибавка на каждый HTTP-запрос**; при повторе `replayed=true`.
- Монеты — игровые баллы; списаний и обмена на деньги нет. Баланс возвращается строкой, чтобы не терять точность `bigint` в JavaScript.
- Один голос на учётную запись в каждом голосовании, его можно изменить до закрытия. Дети и родители голосуют отдельно; учитель видит только агрегированные результаты. Это не голосование «одна семья — один голос». Голоса не утверждают автоматически мероприятие или расходы.
- Сессии: случайный bearer token 256 бит, в БД только SHA-256, срок по умолчанию 8 часов, выход отзывает токен. Пароли: scrypt N=65536/r=8/p=2, индивидуальная соль. Смена пароля отзывает все сессии; блокировка аккаунта действует сразу.
- JSON проверяется Zod, неизвестные поля записи отклоняются. SQL параметризован; ответы об ошибках скрывают внутренние детали. Запросы, тела, авторизация и персональные данные не пишутся в журнал приложения. Есть ограничения размера, IP-частоты и постоянный лимит входа на логин (10 попыток/15 минут), включая успешные входы. Раз в сутки выполняйте `cleanup`.

## Локальная разработка

Нужны Node.js 24, npm и PostgreSQL 17. Используйте отдельную тестовую БД, **не рабочую**.

```sh
cd backend
npm ci
export DATABASE_URL='postgresql://postgres:LOCAL_PASSWORD@127.0.0.1:5432/klasskvest_dev'
npm run migrate
npm run build
npm run dev
```

Для тестов укажите URL одноразовой БД:

```sh
DATABASE_URL='postgresql://postgres:LOCAL_PASSWORD@127.0.0.1:5432/klasskvest_test' npm test
npm audit --omit=dev --audit-level=high
```

Без `DATABASE_URL` выполняется только тест паролей, интеграционный набор явно пропускается. CI всегда поднимает PostgreSQL и проверяет миграции дважды, RBAC/изоляцию классов/согласие, сессии, задания, параллельные начисления, откат и голосования. Docker проверяется отдельной сборкой и запуском Compose.

## API v1 (начальный контракт)

Все защищённые запросы: `Authorization: Bearer <token>`. Ответы `Cache-Control: no-store`. Cookies не используются, CORS не включён. Планируемое подключение интерфейса — на том же домене за HTTPS; токен держать в памяти, не в localStorage. Ключ ответа не должен попадать в клиентский код.

| Метод и путь | Кто / тело |
| --- | --- |
| `POST /api/auth/login` | `{login,password}` → `{token,tokenType,expiresIn}` |
| `POST /api/auth/logout` | Любой вошедший → 204 |
| `GET /api/me` | Только собственные `{user:{id,role}}` |
| `GET /api/classes` | Только доступные классы, до 100 |
| `POST /api/classes` | Учитель: `{title}` → `{id,title}` |
| `GET /api/classes/:classId/bank` | Участник → `{coins:"30"}` |
| `GET /api/classes/:classId/tasks?after=UUID` | Участник, 100 записей, курсор = последний id |
| `POST /api/classes/:classId/tasks` | Учитель класса: `{question,options:["4","5"],correctIndex:0,reward:30}` |
| `POST /api/classes/:classId/tasks/:id/answers` | Ученик класса: `{selectedIndex:0}` |
| `GET /api/classes/:classId/polls?after=UUID` | Участник: только своя аудитория; учитель: обе |
| `POST /api/classes/:classId/polls` | Учитель: `{title,audience:"student" или "parent",options:["A","B"],closesAt:"2026-12-01T12:00:00Z"}` |
| `POST /api/classes/:classId/polls/:id/votes` | Соответствующая аудитория: `{optionIndex:0}` → 204 |
| `GET /api/classes/:classId/polls/:id/results` | Только учитель класса → `{counts:[{option_index:0,votes:5}]}` |
| `GET /health/live`, `GET /health/ready` | Внутренние проверки процесса / БД и миграций |

Индексы вариантов начинаются с 0. Вариантов 2–6, награда 1–1000, срок голосования до 90 суток. HTTP: 400 некорректный ввод; 401 нет сессии; 403 запрещённая роль; 404 чужой/несуществующий объект; 409 конфликт/закрытое голосование; 429 превышен лимит. `requestId` помогает сопоставить обезличенную ошибку. GET-списки имеют ограничение; живой баланс пока можно опрашивать, например раз в 15 секунд. WebSocket не реализован.

## Отдельный Droplet Ubuntu

Не запускайте эти команды на сервере ARGWork. Подготовьте **новый** Ubuntu Droplet и отдельный домен; технически достаточно 2 vCPU/4 GB для небольшого пилота, нагрузочную проверку ещё нужно провести. Регион выбирайте после проверки требований к данным детей; демонстрационный пилот до этого — только вымышленные данные.

1. Создайте SSH-ключ и отдельного пользователя с sudo, проверьте вход перед отключением паролей/root SSH. Установите обновления Ubuntu и Docker Engine с Compose plugin [по официальной инструкции](https://docs.docker.com/engine/install/ubuntu/). Членство в группе docker даёт доступ уровня root.
2. В DigitalOcean Cloud Firewall откройте 22 только своему IP, 80/443 — посетителям. Не открывайте 3000/5432. При использовании UFW учитывайте, что опубликованные Docker-порты обходят обычные правила UFW. В Compose опубликованы только порты прокси 80/443.
3. Настройте DNS A на новый IP. AAAA добавляйте только при работающем IPv6. Доступ извне к 80/443 необходим для HTTPS. Здесь Caddy заменяет Nginx + отдельный Certbot и автоматически управляет сертификатами.
4. Склонируйте репозиторий в `/opt/klasskvest`, выберите проверенный commit/release. Выполните:

```sh
cd /opt/klasskvest
cp .env.example .env
# Укажите настоящий DOMAIN и ACME_EMAIL в .env
install -d -m 700 secrets
umask 077
openssl rand -hex 32 > secrets/db_owner_password
openssl rand -hex 32 > secrets/db_app_password
docker compose config --quiet
docker compose up -d --build
docker compose ps -a
docker compose logs --tail=50 migrate api proxy
docker compose exec -T api node -e "fetch('http://127.0.0.1:3000/health/ready').then(r=>{if(!r.ok)process.exit(1);console.log(r.status)})"
curl --fail https://YOUR_DOMAIN/health/live
```

Файлы секретов не коммитятся. Compose secrets здесь — файлы на диске, **не зашифрованное хранилище**: защитите SSH, доступ к Docker и резервные копии. При первом старте PostgreSQL создаёт отдельного ограниченного пользователя API; миграции/CLI используют владельца. API не может менять пользователей/согласия/чужие роли или удалять/редактировать журнал монет. Не используйте учётную запись владельца в API. Init-скрипт выполняется только на пустом томе; простая замена файла пароля не меняет пароль уже созданной БД.

Производственный API доверяет только одному прокси-переходу. Не публикуйте его порт и не добавляйте другие сервисы к сети `edge`: Caddy должен оставаться единственным входом снаружи. Caddy не сохраняет access log. Compose не сервирует демонстрационный HTML автоматически.

### Первый учитель и участники

Пароль вводится через stdin и не попадает в аргументы процесса/историю. Пример для bash на новом Droplet:

```sh
read -rsp 'Пароль (от 12 символов): ' KK_PASSWORD; printf '\n'
printf '%s' "$KK_PASSWORD" | docker compose run --rm -T migrate node dist/admin.js user teacher_pilot teacher Teacher
unset KK_PASSWORD
```

Сохраните возвращённый UUID в закрытом реестре оператора. Учитель входит через `/api/auth/login` и создаёт класс API-запросом. Аналогично создайте `student` и `parent` с псевдонимами, затем:

```sh
docker compose run --rm -T migrate node dist/admin.js member CLASS_UUID STUDENT_UUID
docker compose run --rm -T migrate node dist/admin.js member CLASS_UUID PARENT_UUID
docker compose run --rm -T migrate node dist/admin.js guardian PARENT_UUID STUDENT_UUID CONSENT_RECORD_ID
```

Учитель-создатель включается в класс автоматически. Дополнительных учителей добавляет оператор `member`. Доступ до назначения членства/согласия не предоставляется. Оператор проверяет реальную личность родителя и его полномочия вне системы; CLI не делает этого автоматически. Передавайте индивидуальные пароли по закрытому каналу. Потерянные пароли сбрасывает оператор командой `password USER_UUID` через stdin. Нет открытого восстановления по email, приглашений по общему коду или MFA; перед массовым запуском нужны проверенные процессы выдачи/смены паролей и защита операторского доступа.

Дополнительные команды: `disable USER_UUID`, `remove-member CLASS_UUID USER_UUID`, `revoke-consent PARENT_UUID STUDENT_UUID`, `cleanup`. Запускайте в том же формате `docker compose run --rm -T migrate node dist/admin.js ...`. Запланируйте `cleanup` раз в сутки от защищённого оператора. При отзыве согласия доступ ребёнка сохраняется, если действует согласие другого активного родителя.

### Обновления и резервное копирование

Снимайте резервную копию **перед** миграциями и ежедневно. Пример выгрузки с нового сервера (не храните в публичном каталоге):

```sh
install -d -m 700 backups
umask 077
docker compose exec -T db pg_dump -U klasskvest_owner -d klasskvest -Fc > backups/klasskvest.dump
# Шифруйте и копируйте вне Droplet; контролируйте код возврата и проверяйте восстановление.
```

Секреты сохраняйте отдельно в защищённом хранилище. Для восстановления используйте отдельный **пустой** тестовый Compose project/сервер, затем `pg_restore -U klasskvest_owner -d klasskvest --no-owner` через stdin внутри контейнера db. Сначала проверьте вход, баланс и ссылки родителей; никогда не испытывайте восстановление поверх рабочих данных. После восстановления отзовите старые сессии (`DELETE FROM sessions` владельцем).

Обновление: проверьте CI, сохраните commit текущей версии и backup; `git pull --ff-only`, `docker compose build`, `docker compose run --rm migrate`, `docker compose up -d`. Миграции сериализуются advisory lock и применяются транзакционно один раз. Откат кода возможен только при совместимой схеме; разрушительные миграции в этом MVP не предусмотрены. `docker compose down -v` **удаляет данные**, не используйте при обновлении. Плавающие теги образов выбирают обновления при pull; для рабочего релиза зафиксируйте проверенные digest и регулярно обновляйте их после тестов.

## Детские данные: границы пилота

В БД нет ФИО, телефонов, email, даты рождения, адресов, координат или чатов. Используйте случайные логины и нейтральные псевдонимы; не вписывайте персональные данные в названия классов/задания/голосования. Связи родителей, учебные ответы и даже псевдонимы всё равно считаются чувствительной информацией и требуют закрытого доступа.

Перед использованием реальных данных определите оператора данных, допустимое место хранения/резервного копирования, правовое основание и форму родительского согласия, сроки хранения и процедуру удаления/выгрузки. Автоматического удаления/анонимизации, интерфейса согласий, аудита действий оператора и юридической проверки ещё нет. Запрос на удаление требует отдельной проверенной процедуры с учётом внешних ключей и согласованности копилки; блокировка аккаунта **не удаляет** данные. Учителя не получают индивидуальные голоса и ответы через этот API; сводки малых групп не публикуются детям/родителям. Поддержка и оператор не должны экспортировать рабочую БД в публичные issues или CI.

Документация по механизмам: [Fastify validation](https://fastify.dev/docs/latest/Reference/Validation-and-Serialization/), [PostgreSQL constraints](https://www.postgresql.org/docs/17/ddl-constraints.html), [PostgreSQL locking](https://www.postgresql.org/docs/17/explicit-locking.html).
